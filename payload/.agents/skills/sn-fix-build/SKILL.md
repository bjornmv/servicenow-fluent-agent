Verified against: now-sdk 4.13.6 local `now-sdk build` output; every row of the table below was reproduced in a throwaway project. On another SDK version match on the quoted message text, not the number.
Diagnose and fix a build failure in this Fluent project. Use `now-sdk` directly in VS Code PowerShell from the confirmed project directory (project `cwd`). See the [SDK command policy](../../reference/sdk-commands.md).

Use the build output from the argument only if it is the complete output of a build of the current source. Otherwise (nothing pasted, partial, another directory, or source edited since) run `now-sdk build` first and keep its full output and native exit status.

## Steps
1. Triage. This skill fixes Fluent compile errors in `.now.ts` files. These are not:
   - `Could not find package.json` (build still exits 0): wrong directory. Confirm the project directory; edit nothing.
   - `TS2307: Cannot find module '@servicenow/sdk/core'` together with `TS2708: Cannot use namespace 'Now' as a value`: project dependencies are not installed. Do not edit source; follow Package managers in the command policy.
   - A diagnostic whose file is under `src/server/`: ordinary TypeScript in a server module. Fix it as TypeScript; the Fluent rules and the table below do not apply.
   - Lux/AIUX or Vite UI bundling failures: use **sn-lux-build** / **sn-ui-page-vite**. Install errors: use **sn-build-install**.
2. Group the output into defects, each with file + line + message. One defect prints several lines:
   - `Node kind "X" is not allowed in Fluent files`, `Declaration kind ...`, `Inline functions are not valid` or `Table definition should be exported` is the primary; `Unsupported variable initializer`, `Failed to parse property` and `Unsupported statement in Fluent source file.` on the same statement, and `TS6133` on the same declaration, are echoes of it. When only those echo lines are printed, use the `TS226` / `TS303` rows.
   - `[now-sdk] ERROR: Plugin "<X>Plugin" failed to transform ... (source: <file>): <reason>` has no line number. It normally comes with a `TS2345` / `TS2322` / `TS27xx` diagnostic for the same record; treat both as one defect and fix that one.
   - Parser codes below about 400 (`TS57`, `TS226`, `TS303` ...) are the TypeScript node-kind number of the rejected syntax, not an error id: the same number carries different messages and can shift with the SDK's bundled TypeScript. Match on the quoted text. tsc codes (`TS2xxx`, `TS6133`) are stable.
   - `Found N diagnostic error(s)` counts diagnostics, not defects; it is not a progress measure.
3. Classify the file before mapping the error: ordinary declarative record, documented ATF/automation/Playbook callback DSL, GraphQL imported-script form, or transformed/Fluent-locked automation. See [Fluent rules](../../instructions/fluent.instructions.md).
4. When the fix touches a record's properties, imports or `$id`, confirm the shape first with `now-sdk explain <topic> --format raw` for the constructor on the failing line. The topic is usually the lowercased constructor plus `-api` (`BusinessRule` → `businessrule-api`); if it answers `No matching topics`, find the name with `now-sdk explain --list "<keyword>" --format raw` (see [sn-explain](../sn-explain/SKILL.md)). Skip this for pure syntax fixes (unused binding, `+`, `||`, `var`).
5. Apply ONE coherent fix for one defect. Do not externalize a documented `Test(...)`, automation, or Playbook builder callback. For ordinary record script fields, move executable logic to an external module. For GraphQL, use a named imported server function (preferred); `Now.include` only for a raw resolver script file, never an `export function` module; inline resolver functions are invalid. For transformed/Fluent-locked automation, do not hand-edit or delete generated source to satisfy the compiler: stop, report the file and diagnostic, and follow [Automation ownership](../sn-build-install/SKILL.md#automation-ownership).
6. Rebuild: `now-sdk build`, only after the previous build's completion is attributable (command policy; UNKNOWN is a stop, not a retry). Report the new output. The build passed only with native exit 0 AND the line `Build completed successfully` AND no `[now-sdk] ERROR:` line. If it still fails, repeat from step 2 with the next defect. Stop and report instead of guessing when a diagnostic matches no row below and `explain` does not settle it, or when the same diagnostic (same file and message) survives two fix attempts. Never change `legacyChoices` / `--legacyChoices` as a parser-error workaround; the default is already the legacy v3 output (see **sn-build-install** Choice compatibility).

## Error → cause → fix

| Diagnostic (match the text) | Fluent cause | Fix |
|---|---|---|
| `TS2322` `Type 'string' is not assignable to type 'boolean'` / `'number'` | Boolean/numeric property given a string: `'true'` / `'100'` | Use the primitive: `true` / `100`. If the diagnostic says the position expects a string (for example Playbook `launcherInputs ... must be a string value`), keep the string. Not every quoted value is caught: column `maxLength: '100'` and a quoted Boolean/Integer column `default` build clean, so a passing build does not prove primitives are right. |
| `TS2820` `Type '"x"' is not assignable to type '"a" \| "b"'. Did you mean ...` | String outside the property's allowed values | Use one of the values listed in the message. |
| `TS2353` `Object literal may only specify known properties, and '<x>' does not exist in type ...` | Property the type does not have: `{ text: '...' }` on a choice, `$id` on `SPPage`, a misspelt or invented property | Choice: `{ label: '...' }`. `SPPage`: remove `$id`, identify the page with `pageId`; `$id` belongs on its containers, rows, columns and widget instances. Otherwise use the property name from the explain output. |
| `TS2304` `Cannot find name 'X'` | Symbol referenced but not imported — usually after splitting a record into multiple files or pasting an example without its imports | Add the missing import from the path shown by the explain output (typically `@servicenow/sdk/core`; `@servicenow/sdk/automation` for the Flow and Playbook DSL). Do NOT hand-guess the import path — it can shift between SDK majors. |
| `TS213` `Table definition should be exported as a named export with the name '<table>'` on the table file (often with `TS6133` on the same `const`); `TS2459` / `TS2305` on a file that imports the table | `Table({...})` has no named export, or export name ≠ table name | `const x_acme_foo = Table({...}); export { x_acme_foo };` or `export const x_acme_foo = Table({...})` — name must equal the table name. Do not delete the `const` to silence the `TS6133`. |
| `TS2345` `Argument of type ... is not assignable to parameter of type '<Record>'` with a nested `Property '<x>' is missing ... but required` | Record call missing a required top-level property (e.g. `Table` without `name`, `BusinessRule` without `table`, `SPPage` without `pageId`) | Add `<x>` as a primitive; the explain output shows the required set. If `<x>` is `$id`, use the next row. |
| `Failed to determine ID for "<table>" record` (plugin line) with `Property '$id' is missing` under `TS2345` (top-level record) or `TS2322` (nested object such as an `SPPage` container/row/column/instance) | Record or nested record missing `$id` — required on `BusinessRule` and most non-Table records (typed `WithID`) | Add `$id: Now.ID['<stable_key>']` to that object; the key is the record's stable identity in `keys.ts` (see `explain keys-file`). `Table` uses the named export instead; `SPPage` itself uses `pageId`. |
| `TS2741` `Property '<x>' is missing in type` / `TS2739` `is missing the following properties` | Nested object literal missing required properties (e.g. a `Table` `index` entry without `element` / `unique`) | Add every property the message names. An accompanying `Plugin ... failed to transform` line with an opaque reason is the same defect. |
| `Record "<table>.<sys_id>" is defined N times in the project` followed by a numbered `file:line` list | Two records resolve to the same identity (same `$id` key, or the same record defined twice) | Remove the duplicate definition, or give a genuinely separate record its own `$id` key. |
| `TS6133` `'<name>' is declared but its value is never read` | Unused binding in the `.now.ts`: helper `const` or import specifier (common after removing a record or externalizing a script) | Delete it (trim the import list) or reference it. Exceptions: on a `Table` `const` with `TS213`, export it; on a parameter of an inline `function` in a property, externalize the function (see the `TS303` row). |
| `Node kind "BarBarToken"` (`TS57`) / `"AmpersandAmpersandToken"` (`TS56`) / `"ConditionalExpression"` (`TS227`) `is not allowed in Fluent files` | `\|\|`, `&&`, or `?:` in an unsupported ordinary-record position; moving it to a scalar `const` reproduces the error | Resolve the ordinary property to a literal at authoring time, or move runtime logic into an external script. For a documented DSL file, compare the exact failing shape with its API/guide instead of applying this row mechanically. |
| `TS226` `Unsupported variable initializer` on a `const` (arithmetic also prints a `Node kind "AsteriskToken"`-style line; `+` prints no node kind) | Binary expression in a `const` initializer: `+` string concat or arithmetic | Rewrite string composition as a template literal; write an arithmetic result as the literal. Preserve API-documented DSL helper assignments. |
| `TS303` `Failed to parse property` + `TS244` `Unsupported statement in Fluent source file.` with no more specific line | The property value at the reported column is unsupported syntax: an inline `function (...) {...}` (often with `TS6133` on its parameters), or a `+` expression | Ordinary record script: externalize with the API-supported form (`Now.include` or a named function imported from `src/server`). `+`: template literal. Classify first; preserve exact API-documented ATF/automation/Playbook callbacks. |
| `TS219` `Inline functions are not valid. Use a named function imported from a server module in 'src/server', a string literal, or with Now.include().` | Arrow function as a property value or `const` initializer | As the message says. GraphQL uses a named imported server function; `Now.include` there only for a raw resolver script file. |
| `TS80` `Unable to resolve the reference, ensure the imported module is within the src/server directory.` | `script` references a function declared in the same `.now.ts` (with `TS262` `Unsupported statement`), or one imported from a path that does not resolve (with `TS2307`) | Put the function in a module under `src/server` and import it by the correct relative path from the `.now.ts`. |
| `TS11` `Failed to include file. Reason: No file found at path: <path>` | `Now.include('<relative>')` path does not exist; it resolves relative to the `.now.ts` file | Correct the relative path or create the file at the printed path. |
| `Declaration kind "var"` (`TS115`) / `"let"` (`TS121`) `is not supported. Only const variables are supported.` | `var` / `let` in a Fluent file | Use `const`. |
| `Node kind "IfStatement"` / `"ForStatement"` / `"ForOfStatement"` / `"WhileStatement"` / `"SwitchStatement"` / `"NewExpression"` `is not allowed in Fluent files` | Either unsupported executable syntax in an ordinary record, or a documented DSL callback was authored in the wrong shape | Classify first. Preserve exact API-documented ATF/automation/Playbook callbacks. For an ordinary record, move runtime logic to an external module. Current `TestSuite` and `GraphQLApi` are direct calls, not `new` expressions. |
| `Node kind "SpreadAssignment"` (`TS305`) / `"ShorthandPropertyAssignment"` (`TS304`), both with `Only property assignments are allowed`, / `"SpreadElement"` (`TS230`) `is not allowed in Fluent files` | Object spread (`{ ...base }`), shorthand property (`{ a }`, also in a DSL callback's returned object) or array spread (`[...list, 'x']`) in an unsupported position | Shorthand: write `{ a: a }`. Write the ordinary record object or array explicitly, or move runtime assembly to an external script. For a documented DSL, follow its exact supported shape; do not assume arbitrary spread is accepted. |

## Rules
- One coherent fix per build cycle; rebuild after each. Print each command before running it. Terse output, no emojis.
