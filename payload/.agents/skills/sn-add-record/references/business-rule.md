# Business-rule traps

Authoring reminders; where they differ from the project's `now-sdk explain` output, the explain output wins.

- Read `businessrule-api`; read `business-rule-guide` for the first project rule or an unfamiliar trigger pattern.
- Place the file next to the project's existing hand-authored rules and follow their naming. Use `src/fluent/server-development/business-rule/<name>.now.ts` only when the project has no hand-authored `.now.ts` layout yet or already uses that one; keep round-tripped transform output under its generated layout.
- A stable `$id: Now.ID['<stable_key>']` is required for BusinessRule. Missing identity produces TS2345 / "Failed to determine ID". A key such as `br_<name>` becomes the record's identity in `keys.ts`; do not churn existing keys, because renaming a key creates a new record and orphans the old one.
- Require `name`, `table` and every other field the actual API marks required. Set `when` and `action` deliberately from the documented values: both are optional, and a rule built without `action` is emitted with the insert, update, delete and query flags all false. Use primitive numeric `order` and boolean `active`, never `'100'` or `'true'` strings (TS2322).
- Confirm the exact table name before authoring: a table defined in this project's source, or one the user confirms or a bounded [sn-rest](../../sn-rest/SKILL.md) read shows. An unknown table name built without error, so a passing build is not evidence that the table exists.
- Externalize executable logic; an inline function body is a build error (TS219). Follow the form the project's existing rules use, otherwise choose by the script:
  - Server module (the form `business-rule-guide` prefers for new logic): export a named function `(current, previous)` from a file under the project's server-modules directory (`serverModulesDir`, default `src/server`), import it into the `.now.ts` and pass `script: <functionName>`. No IIFE wrapper. An import from outside that directory fails with TS80. JavaScript or TypeScript both build. Inside a module, import Glide APIs from `@servicenow/glide` and Script Include classes from `@servicenow/glide/<scope>` (`@servicenow/glide/global` for global ones) instead of scope-prefix globals; see `module-guide`.
  - `script: Now.include('<relative path>.js')`: for an existing non-modular script, or a project that already keeps record scripts under `src/scripts/`. The file text is inlined verbatim as the script body, so it must be plain JavaScript; TypeScript syntax there is not compiled and still builds green. The classic platform wrapper `(function executeRule(current, previous) { ... })(current, previous);` and bare statements using `current`/`previous` both build. The path is relative to the `.now.ts` file: from the depth-3 layout above it is `'../../../scripts/<name>.js'`; recalculate from the actual location rather than copying it blindly.
- Runtime logic belongs in that module or script, not in declarative record properties or scalar const initializers. The [Fluent rules](../../../instructions/fluent.instructions.md) for ordinary records still apply to the `.now.ts` declaration (for example no `||`, `&&`, `?:`, object spread, string `+` composition, runtime control flow or unused consts). Confirm the trigger and previous-record behavior against the guide rather than inventing semantics.
